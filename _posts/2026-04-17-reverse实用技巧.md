  反编译：**IDA pro**，如果不会破解可以用 Ghidra 平替。

# 实用操作


## IDA 基础操作

| 快捷键      | 功能                | 使用场景                             |
| :---------- | :------------------ | :----------------------------------- |
| `F5`        | 反编译成伪代码      | 看C/C++逻辑                          |
| `Shift+F12` | 打开字符串窗口      | 找线索("Correct!", "Wrong!"等)       |
| `G`         | 跳转到地址          | 定位函数/数据                        |
| `X`         | 查看交叉引用        | 找谁调用了这个函数/用了这个字符串    |
| `N`         | 重命名              | 把 `sub_401000` 改成 `base64_decode` |
| `Y`         | 修改变量/函数类型   | 调整参数个数/类型                    |
| `U`         | 取消定义(Undefine)  | 把错误识别的代码/数据还原成字节      |
| `C`         | 定义为代码(Code)    | 把字节强制转成汇编指令               |
| `D`         | 定义为数据(Data)    | 把字节强制转成数据                   |
| `A`         | 定义为字符串(ASCII) | 把字节转成可读字符串                 |
| `P`         | 创建函数            | 手动告诉IDA从这里开始是一个函数      |
| `H`         | 十六进制 ↔ 字符切换 | 看数字对应的ASCII字符                |
| `Ctrl+X`    | 交叉引用该行地址    | 类似 `X`                             |
| `Ctrl+E`    | 查看导出表(Export)  | DLL文件找导出函数                    |
| `Alt+P`     | 编辑函数属性        | 修改函数边界/栈指针                  |
| `Alt+K`     | 修改栈指针          | 修复 `sp-analysis failed`            |
| `Alt+F7`    | 运行IDC脚本         | 批量NOP、批量修改                    |

## 常见加密/算法特征识别

### 1. XOR 加密

**特征**：

```c
for (i = 0; i < len; i++)
    output[i] = input[i] ^ key[i % key_len];
```

**识别方法**：

- 找 `^` 运算符
- 找循环里对每个字节做异或

**解密**：XOR 是可逆的，`plain = cipher ^ key`

### 2. Base64

**特征**：

- 64个字符的码表（`ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/`）
- 移位操作：`v14 = v16 & 0x3F | (v14 << 6)`
- 处理 `=` 填充符

**识别方法**：

- 找长字符串包含大小写字母+数字+`+/`
- 找循环里每次处理3字节输出4字节

### 3. MD5

**特征**：

- 四个初始化常量：
  - `0x67452301`
  - `0xEFCDAB89`
  - `0x98BADCFE`
  - `0x10325476`
- 填充：`ptr[n] = 0x80`
- 循环处理每组64字节

**识别方法**：

- 在 IDA 中搜索 `0x67452301` 或 `0xEFCDAB89`
- 找 `0x80` 填充

### 4. RC4

**特征**：

- KSA（密钥调度）：256次循环，打乱S盒
- PRGA（伪随机数生成）：逐字节异或

**KSA 特征**：

```c
for (i = 0; i < 256; i++) {
    j = (j + S[i] + key[i % len]) & 0xFF;
    swap(S[i], S[j]);
}
```

**PRGA 特征**：

```c
i = (i + 1) & 0xFF;
j = (j + S[i]) & 0xFF;
swap(S[i], S[j]);
output = input ^ S[(S[i] + S[j]) & 0xFF];
```

### 5. AES/RSA

**特征**：

- AES：找 `0x63`、`0x7C`、`0x77` 等S盒常量
- RSA：找大数运算（`0x10001` 常作为公钥指数）

## 反调试与反混淆

### 1. ptrace 反调试

**特征**：

```c
if (ptrace(PTRACE_TRACEME, 0, 1, 0) < 0) {
    // 被调试，退出
}
```

**绕过方法**：

```bash
(gdb) b ptrace
(gdb) return 0
```

### 2. IsDebuggerPresent

**特征**：

```c
if (IsDebuggerPresent()) exit(1);
```

**绕过方法**：

- 修改 `PEB.BeingDebugged` 为 0
- 或直接 patch `IsDebuggerPresent` 返回 0

### 3. PIE（地址随机化）

**现象**：每次运行地址不同，断点下不了

**绕过**：

```bash
(gdb) set disable-randomization on
```

或使用硬件断点 `hb *地址`

### 4. 花指令（Junk Code）

**常见模式**：

| 模式                 | 示例                | 处理          |
| :------------------- | :------------------ | :------------ |
| `jz`+`jnz`跳同一地址 | `jz loc; jnz loc`   | NOP掉         |
| `push`+`retn`        | `push addr; retn`   | NOP掉或跟进   |
| `call` 后跟垃圾字节  | `call sub; db 0C7h` | NOP掉垃圾字节 |
| `jmp` 到无效地址     | `jmp 0x6F44B961h`   | NOP掉         |

**修复方法**：

1. 找到垃圾指令范围
2. 全部改成 `0x90`（NOP）
3. 在真正的代码处按 `U` → `C` 重新分析

### 5. JUMPOUT

**现象**：伪代码中出现 `JUMPOUT(地址)`

**原因**：函数不是正常 `retn` 结束，而是跳转到其他地址

**修复**：

- 跟进跳转地址，分析真正的代码
- 或删除函数，在正确地址重新 `P`

### 6. sp-analysis failed

**原因**：栈指针不平衡（函数开头和结尾 `esp` 不一致）

**修复**：

- 在 `retn` 处按 `Alt+K`，设置栈指针为 `0`
- 或在函数开头按 `Alt+P` 调整函数边界

## 四、C++ 逆向特征

### 1. std::string

**在 IDA 中的样子**：

```c
struct std_string {
    char *ptr;      // 指向数据
    size_t size;    // 长度
    size_t capacity; // 容量
};
```

**识别方法**：

- 看到 `magic` 结构体（24字节）
- 看到 `std::string::` 开头的函数名

### 2. std::vector

**在 IDA 中的样子**：

```c
struct std_vector {
    void *start;    // 指向数据开始
    void *end;      // 指向数据结束
    void *capacity; // 指向容量结束
};
```

### 3. lambda 表达式

**在 IDA 中的样子**：

- 函数名包含 `lambda_xxx`
- 会生成 `operator()` 成员函数

## 静态修复流程

### 场景1：函数无法 F5（sp-analysis failed）

1. 找到函数末尾的 `retn`
2. 按 `Alt+K`，把栈指针改成 `0`
3. 或删除函数（`Alt+P` → Delete）
4. 在正确地址按 `P` 重新创建函数

### 场景2：花指令导致代码/数据错乱

1. 找到垃圾指令范围
2. 用脚本批量 NOP 掉（`PatchByte(addr, 0x90)`）
3. 在真正的代码处按 `U` → `C`
4. 按 `P` 创建函数
5. 按 `F5` 反编译

### 场景3：函数被拆分成多个（混淆）

1. 找到真正的函数开头（通常是 `push ebp`）
2. 按 `U` 取消所有错误定义
3. 按 `P` 创建完整函数
4. 按 `F5`

## 批量 NOP 脚本（IDC）

```c
#include <idc.idc>
static main() {
    auto start = 0x004116C8;  // 改你的起始地址
    auto end   = 0x004117A0;  // 改你的结束地址
    auto addr;
    for (addr = start; addr < end; addr++) {
        PatchByte(addr, 0x90);
    }
    Message("NOP from 0x%x to 0x%x done\n", start, end);
}
```

## 解题通用流程

```txt
1. file 查看文件类型
2. strings 查看字符串线索
3. IDA 打开，Shift+F12 看字符串
4. 找 "Correct!" / "Wrong!" / 可疑字符串
5. X 交叉引用，跳转到使用位置
6. F5 看伪代码
7. x 看v单变量干了什么
8. 识别算法（XOR / Base64 / RC4 / MD5）
9. 提取密钥和密文
10. 写 Python 脚本解密
11. 如果 F5 失败 → 检查花指令 / 反调试
```
