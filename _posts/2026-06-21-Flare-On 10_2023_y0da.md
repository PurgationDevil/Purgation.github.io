# Flare-On 10_2023_y0da

## 前言

这道题出自全球顶级逆向工程与恶意软件分析专场赛事：**Flare-On 10（2023年举办）的第 13 题（压轴最终关卡 `y0da`）**。出题难点的是当年最恐怖的混淆技术：**代码碎尸**。

**原型背景**：它的混淆手法并不是凭空想象的，而是出题人根据现实中真实发生的 **KNOTWEED 组织网络雇佣兵恶意软件（名为 JUMPLUMP 的特工特洛伊木马）**为原型设计的。

**`y0da` 读作“Yoda”（尤达）**，就是《星球大战》里那位活了 900 岁、说话颠三倒四的 **尤达大师（Master Yoda）**。RC4 最终解密密钥，也就是 `patience_y0u_must_h4v3`。这句台词完全模仿了尤达大师经典的**“倒装句”**语法（正常语序是：*You must have patience*，即“你必须保持耐心”）。

## y0da.exe 分析

### start 分析

拿到程序后首先就是看汇编，像这种混淆反编译和任何的自动化工具都是没有用的。

```assembly
sub     rsp, 28h
jmp     loc_1800136A2
endp
```

`start` 函数只有跳转，跟进去看看

```assembly
call    sub_18000853F
jmp     loc_1800340C9
```

这里只调用了一个函数，继续跟进 `jmp`

```assembly
add     rsp, 28h
jmp     nullsub_2
```

`null` 注意

```assembly
nullsub2	proc near
			retn
nullsub2	endp
```

这是一个标准的 “什么都不干、直接返回” 的空函数。选择 `nullsub2`，Delete function。（这里不按 U 或 nop 调整）

然后把这里加一个 `start` 调用该函数的说明。（append function tail...）这样再切换图形界面就好多了。

```assembly
; FUNCTION CHUNK AT .text:00000001800136A2 SIZE 0000000A BYTES
; FUNCTION CHUNK AT .text:0000000180016D82 SIZE 00000001 BYTES
; FUNCTION CHUNK AT .text:00000001800340C9 SIZE 00000009 BYTES
```

修复完成后，IDA 成功识别到：这个 `start` 函数并不是一段连续的代码，它被出题人**活生生肢解成了散落在内存各处的 3 个独立代码碎片**

现在，第一个函数 `start` 修复完毕。虽然是被分成几个小块，但是经过了上面的修复已经成功的在图形界面中可以完整的显现从来一个完整的函数。这就是恐怖的混淆技术：**代码碎尸**。

下面继续分析 `start` 函数调用的唯一函数 `sub_18000853F`。

与整理前的 `start` 一样，这个函数同样是分成了无数碎尸。

从上面分析的经验以及这次的 `jmp` 跳转跟进，很显然 IDA 已经很尽力把这些碎尸合并了。

`jmp` `jmp` `jmp`，在 `sub_18000853F` 下的 `sub_180034E4F` 独立成函数了。

由于每条指令都被破坏和移动，它可能有自己的独立代码块。

把 `sub_180034E4F` 函数 Delete function 然后 append function tail... 这样就又会多一个分析成功的函数。

但是这样太慢了。
